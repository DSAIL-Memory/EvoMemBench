## 2. Honest collisions between vision and standing invariants

1. **BFCL prohibition is absolute and the vision's richest op surface lives there.** The only place in the whole repo with literal `memory_add/update/delete/clear`-style tools is the BFCL memory suite (`core_memory_*`/`archival_memory_*`, `In-Episode-Execution/INEP-EXEC/.../func_source_code/memory_{kv,vector,rec_sum}.py`) — and both execution trees are banned (`HNAV_AGENT_BRIEF.md:38-39,321`; CLAUDE.md). The ban is doubly justified by the substrate's own scoring: BFCL state_checker requires **exact instance-state match** against gold (`multi_turn_checker.py:162-194`), so any canonicalization, refused write, or archive-instead-of-delete is *scored as a failure even when semantically better*. V4-canonicalization and V5-archival are structurally unmeasurable there. This part of the vision has no legal home in this repo's execution arenas, full stop.

2. **write_policy NO_GO — but read the scope line carefully.** `KAPI_KARARI.md:53-56`: "Tavan yok… Bu, tasarımın değil ARENANIN cevabı" — *the arena's answer, not the design's*: in single-hop fact-consolidation, retrieval already finds LATEST and the veto chain leaves ~0–1.6% headroom (could-change-correctness ≈ 0.00 on sh_64k). The NO_GO was measured on **MemoryAgentBench context-chunks** (append-only, dedup-free substrate where duplicate_rate measured 0.0 everywhere). CrossEp-Know is a **materially different substrate** for the write cascade: real memory APIs with LLM-mediated extraction (mem0 add pays an LLM call per write, `main.py:706-736`; A-mem's process_memory mutates neighbors), free-text candidates without a validated fact parser, and backends where duplicates/near-duplicates *can* accumulate. So extending V2/V3/V4 write-side to CrossEp is **not covered by the measured NO_GO** — but it is also **not authorized by it**: the honest position is "unmeasured, requires its own Stage-0-style headroom measurement and its own [GATE]", not "the ban doesn't apply so build it." Two hard mechanics regardless of arena: `test_no_raw_entropy_in_policy.py` bans `hnav/core/*policy*.py` by glob, and `STAGE1_PLAN.md:5` says the write ban **persists** ("write yasağı sürer") even as the read ban lifts.

3. **Extra inference vs shadow neutrality.** V3 NLI calls and V4 probe/canonicalization LLM calls are extra inference — illegal in shadow ("no store mutation, no extra LLM calls," brief:61-63) and legal only behind `HNAV_MODE=live`, which `config.require_not_live()` refuses until explicitly lifted per-stage. Read_gate's NLI therefore only runs in the sanctioned Stage-1 live-read campaign, never in shadow logging.

4. **Probe questions vs the leakage rule.** Benchmark questions live in the same JSON as the facts; V4's "natural probe questions" must be template-derived from decision-time info only (`conflict_index.py:166-169`), and any probe generator for CrossEp free-text has no relation template to lean on — it would need an LLM probe writer, compounding collision 3. Enforced by the AST scan (`test_leakage_audit.py`, ONLINE_DIRS = core+adapters).

5. **Threshold discipline vs every new vision knob.** Top-1-clarity cutoff, NLI contradiction threshold, cos_pair, escalation triggers — all must be fit on sh_6k+sh_32k and frozen (brief:65-67; `m4_marginal_diff_test.py` refuses non-calibration splits; "sh_64k üzerinde HİÇBİR ayar yapılmaz" `STAGE1_PLAN.md:83`). CrossEp-Know has **no equivalent calibration split defined yet** — a prerequisite artifact, not an afterthought.

6. **V5 has no substrate anywhere measurable.** Primary arena append-only; cl_bench ABC has no destructive verbs; the vendored mem0 fork stripped upstream's UPDATE/DELETE path; MemOS is unimportable locally (`src/memos/memories/` missing from checkout, `registry.py:20-24` sets `_MEMOS_AVAILABLE=False` — flag before budgeting any MemOS runs); real destruction (MemoryOS LFU, MemoBrain pruning) happens below public APIs. V5 as specced cannot currently produce a benchmark number.

## 3. Three biggest technical risks

1. **Read-repair inverts with scale — the one compensation experiment run net-harmed at 262k.** Append-injection: sh_64k +6/−1, sh_262k +3/−5 (`stage0_results/final/m3_headroom.json`; mechanism: stale distractor stays in context, `counterfactual.py:284-285`). The Stage-1 rerank design differs (demote stale, don't append), but the risk is the same shape: any V6 compensator validated at mid-scale may harm at large-scale, and the campaign is single-shot on sh_64k (N=7/arm, success = Δacc ≥ +3 pts AND pooled harm ≤ 2%). A sh_64k win says nothing about 262k, where native accuracy is 0.20 and nmargin p50 has collapsed to 0.0040.

2. **The read gate's precision/coverage coupling may leave it firing on almost nothing.** `read_gate.py`'s own docstring concedes that under the frozen r_min<0.1924, a two-member group's leave-one-out residual `sqrt(1−cos²)` implies pair cosine ≳ 0.981 — while M1b's best-F1 grouping taus were 0.91–0.95. The default gate is "deliberately precision-first until Faz B rebalances it"; the Stage-0 precedent (would_intervene 0.0–1.6% after vetoes; critical_delta_rate 0.0 everywhere; M4 h2 fail) is that precision-first gates in this codebase converge to firing never. Faz B coverage-rebalancing on sh_6k+sh_32k is where this either becomes a real intervention rate or the read cascade repeats the write path's null. Second-order: READ_STALE/READ_CONFLICT are at rate 1.0 (no stratification power), and READ_MISSING/DISTRACTOR currently depend on the **offline** question→key map (`m3_headroom.py:279-282`) — an online query parser is an unbuilt prerequisite for using them live.

3. **CrossEp-Know is instrumented in name but blind in practice, and clustering eats its statistical power.** The wrapper passes literal Nones for geometry/diff/effect (`clbench_adapter.py:100-101`), MemOS is unimportable, backends have no keys/serials (no conflict index, no relation-template probes — `clbench_adapter.py` header notes this), only vector replicas exist (no BM25 for the bm25 backend), and ICC=0.346 / design effect 3.20 cuts effective N to ~276 of 884. Any "the write cascade works on the memory-API arena" claim must first rebuild the entire measurement layer there — signal wiring, a probe strategy for free-text, a calibration split, cluster-robust analysis — before a single policy line is defensible.

## 4. Recommended implementation ordering

Sequenced to reuse the landed read_gate/NLI work and to keep every step inside current authorization until a [GATE]:

1. **Faz A completion (now):** finish testing `hnav/core/read_gate.py` to the repo's closed-form standard (synthetic conflict groups with known components; NLI stubbed via the `NLIClient` protocol; assert `for_policy()` sourcing and `latest_id=None` on ties). Add the NLI-weights check to `hnav/deploy/check_env.py` per `STAGE1_PLAN.md:48-56`.
2. **Faz B — `hnav/core/read_policy.py` (rerank-only):** the sole sanctioned intervention. Update `test_no_raw_entropy_in_policy.py`'s glob deliberately (write half of the ban stays). Wire through the existing injection slot `mab_adapter.py:161,407-413` and implement `apply_read_decision` (`mab_adapter.py:449-454`); execution point is `embedding_retriever.py:251`. Coverage-rebalance cos_pair/r_min on sh_6k+sh_32k only; freeze; run the sh_64k campaign. **This closes V6 and delivers the read half of V8 (geometry→NLI escalation already embodied in read_gate).** [GATE] at campaign readout.
3. **V1 promotion (cheap, parallel):** compute read_gate/geometry signals in ABTT space and log whitened-vs-raw side-by-side in the Faz B shadow logs — one config flag, no new invariant risk; decide from data whether ABTT becomes the operating space.
4. **CrossEp instrumentation repair (measurement only, no policy):** wire injected modules through `CLBenchAdapter.on_extract` (kill the hardcoded Nones), add a free-text probe strategy decision (template-less; likely embed-the-candidate-itself as in `replica.py`'s default), resolve the MemOS checkout, define a CrossEp calibration split, and run a mem0/A-mem write-side headroom measurement (duplicate/near-duplicate base rates, sim_max distributions) — the Stage-0-for-CrossEp that the write-cascade question requires. Reuses `GeometryModule`, `diff_geometry`, `simulate_insert`, and read_gate's NLI client unchanged; all adapter-layer work.
5. **[GATE] Write-cascade decision on CrossEp evidence:** only if step 4 shows real headroom (unlike MAB's 0–1.6%) propose V2-classifier + V3 write-NLI + V4 top-1 check as a *CrossEp adapter policy*, with an explicit human sign-off that the KAPI_KARARI NO_GO scope (arena-specific per its own text, `KAPI_KARARI.md:53-56`) is being extended, not violated. BM25 replica lands here if the bm25 backend is in scope.
6. **V5 archival + V4 canonicalization: last, and only with a substrate.** Defer until a backend with genuine destructive verbs is on a measured path (mem0's dormant update/delete surface is the only realistic candidate, wrapped at `mem0/memory/main.py:1501-1752`); reuse mem0's history table as the archive seed and read_gate's NLI for the last-copy check. Never in BFCL trees under any plan.
