## 0. Get the repo onto the new machine

```bash
git clone https://github.com/kutluege/EvoMemBench.git
cd EvoMemBench
git checkout claude/evomembench-hnav-analysis-nfwl9z
```

- [ ] Cloned and on the right branch (`git log --oneline -1` → `156e772` or later)

**What does not come across, by design:**

| Not in git | Why | What to do |
| --- | --- | --- |
| `.env` | gitignored (secrets) | `cp hnav/deploy/.env.template .env`, then edit |
| `hnav/_cache/` | gitignored, ~26k `.npy` files | Regenerated by T1. First run pays for it; everything after is free |
| `hnav/_out/` | gitignored, all measurement output | Regenerated by T1–T8 |
| `.venv-hnav/` | gitignored | `bash hnav/deploy/setup_remote.sh` |

**Do not** copy `hnav/_cache/` between machines unless the embedder model *and*
dtype match exactly. The cache key is `sha256(model|dtype||text)`, so a mismatch
silently produces a cache miss rather than a wrong answer — but a *matching* key
from a different run of a different dtype would be wrong. Cheaper to regenerate.

## 6. T4 — shadow neutrality  ⚠ TWO CORRECTIONS

> **Correction 1 to PROMPT_B step 7.** `pytest test_shadow_neutrality.py` does
> **not** run the benchmark. It verifies the *mechanism*: hooks return the
> caller's own object by identity, no store is mutated, the wrapper makes exactly
> one inner call, all four edits keep their native branch. The run-level
> byte-identity claim needs two real benchmark runs and is a separate job.

> **Correction 2 to PROMPT_B step 7 — ⚠ THIS CORRECTION WAS ITSELF WRONG.
> Superseded; see below.**
>
> ~~`serve_embeddings.sh` on `:8001` is **not needed** for the MemoryAgentBench
> arena. `Qwen3Embedding4BEmbeddings` (`methods/embedding_retriever.py:52`) loads
> the model **in-process** via transformers.~~
>
> `Qwen3Embedding4BEmbeddings` exists at `embedding_retriever.py:51` but
> **`TextRetriever.__init__` never selects it.** Line 176 routes
> `"Qwen/Qwen3-Embedding-4B"` to LangChain `OpenAIEmbeddings` against
> `OPENAI_BASE_URL`, read via `dotenv.dotenv_values()` — i.e. from the `.env` in
> the **current working directory**, not the repo root. The in-process class is
> dead code on this path.
>
> Consequences: **`:8001` IS required** for M0 and T4, and the MemoryAgentBench
> directory needs its own `.env`. Because embeddings read the file and the LLM's
> bare `OpenAI()` reads only `os.environ`, the two can point at different ports:
> put `OPENAI_BASE_URL=:8001` in `MemoryAgentBench/.env` and `export
> OPENAI_BASE_URL=:8000` in the shell. See `hnav/deploy/mab.env.template`.

The run-level check, on the primary arena:

```bash
cd In-Episode-Knowledge/INEP-KNOW/MemoryAgentBench

# GPU1 only: Qwen3Embedding4BEmbeddings uses device_map="auto" and will
# otherwise allocate on GPU0, where the vLLM server lives.
export CUDA_VISIBLE_DEVICES=1
export OPENAI_BASE_URL=http://localhost:8000/v1
export OPENAI_API_KEY=EMPTY

HNAV_MODE=off    python main.py --agent_config <local-qwen-cfg>.yaml \
                 --dataset_config configs/data_conf/Conflict_Resolution/Factconsolidation_sh_6k.yaml
HNAV_MODE=shadow python main.py --agent_config <local-qwen-cfg>.yaml \
                 --dataset_config configs/data_conf/Conflict_Resolution/Factconsolidation_sh_6k.yaml
# then diff the two result JSONs, ignoring any additive "hnav" key
```

`<local-qwen-cfg>.yaml` **does not exist yet**. The shipped configs under
`configs/agent_conf/RAG_Agents/deepseek-chat/` specify `model: deepseek-chat` and
`temperature: 0.7`. You need a copy with:

- `model:` set to the served id, **without the substring `deepseek`** —
  `agent.py:_handle_embedding_rag` sets `use_deepseek = "deepseek" in self.model`
  and then passes `use_ark_batch=use_deepseek`, which routes through
  `volcenginesdkarkruntime.Ark` instead of the OpenAI client. A non-deepseek name
  falls through to the plain `OpenAI()` branch, which honours `OPENAI_BASE_URL`.
- `temperature: 0` — at 0.7 there is no byte-identity claim to make and the whole
  test is meaningless.
- a distinct `output_dir:` per arm so the two runs do not overwrite each other.

Checklist:

- [ ] Local-Qwen agent config written, `temperature: 0`, non-deepseek model name
- [ ] `HNAV_MODE=off` run completed
- [ ] `HNAV_MODE=shadow` run completed
- [ ] Model outputs byte-identical, per-question `substring_exact_match` identical
- [ ] `stats` token counts unchanged
- [ ] Repeated for `sh_32k`

**Any difference is a bug, not sampling noise.** At `temperature=0` with a
deterministic evaluator there is no legitimate source of variation. Fix before
proceeding — this is S2, a hard stop.

- **Do not delete `hnav/_cache/emb/`.** T1 pays for it once; T2 onward are free.
- OOM on GPU1 → lower `HNAV_EMBED_BATCH` **before** touching dtype. Dtype is pinned.
- Never `HNAV_MODE=live` during Stage 0. `config.require_not_live()` refuses, but
  do not rely on that.

  thresholds without a calibration subset and `m4` refuses a non-calibration
  split outright.

  want to keep must be copied out or committed deliberately.
